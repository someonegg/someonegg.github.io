# Agent 记忆：从原始证据到可复用知识

Agent 在长任务中遇到的一个困难是：第一次接触信息时，往往不知道哪些细节会在以后变得重要。它可能把一次失败归因于错误原因，也可能在压缩上下文时丢掉后来需要的观察。下一次会话继承了结论，却失去了检查结论的依据。

因此，记忆设计需要同时解决两个问题：让已有经验能够高效复用，以及让错误认识能够被证据推翻。前者依赖选择和抽象，后者依赖保真记录与回查能力。

## 一、先区分当前状态、历史证据与提炼知识

“该记住什么”需要先回答“以后还能从哪里得到它”。三类信息具有不同的维护方式：

| 信息类型 | 示例 | 主要处理方式 |
| --- | --- | --- |
| 当前状态 | 现行配置、当前代码、最新监控、当前画面 | 查询现行来源，避免用旧副本指导当前行动。 |
| 历史证据 | 过去的工具返回、动作前后画面、测试报告、用户原始约束 | 保存必要记录，建立时间、任务与版本索引。 |
| 提炼知识 | 已验证规则、决策理由、失败经验、适用条件 | 归纳并关联依据，随新证据修订。 |

例如，排查服务故障时，当前配置应从配置系统读取；故障发生时的配置和指标需要历史记录；“上次为何放弃某项优化”则需要保存决策过程。

这些分类描述的是信息的用途，同一份材料可以承担不同角色。一张截图可以说明当时状态，也可以成为验证某条规则的证据。关键是使用时明确：它描述哪个时刻、支持什么判断。

“记忆是环境的补集”可以提醒我们减少重复记录。环境能够直接提供的现行事实，不必反复抄进笔记。但当前环境通常无法还原过去：界面已经变化，服务已经重启，用户也可能修改了要求。历史记录承担了额外的时间维度。

当经验被整理进共享 Wiki，它又成为未来 Agent 可查询的环境。环境与记忆可以相互转化，二者的边界取决于系统已经提供哪些信息。

## 二、摘要是一种选择，也可能形成错误依赖

保存经验意味着预测未来需求。模型记录一条规则，是在判断后续任务可能再次用到它；略过一个细节，则是在判断保留它的价值不足以抵消成本。

这类判断不可避免地有损。一次按钮点击后出现的短暂提示，可能在当时被认为无关，后来却成为解释失败的关键。若只留下“点击无效”，后续模型就很难区分按钮不可用、请求失败和界面延迟。

错误摘要还有持续放大的风险。推测被写入记忆后，下一次会话可能把它当成已确认事实，再围绕它解释新观察。反复读取增加了熟悉程度，却没有增加证据。

一个实用的工程做法，是让重要结论区分三个状态：

- **观察**：工具或环境实际返回了什么。
- **假设**：目前怎样解释观察，还存在哪些替代解释。
- **已验证规则**：经过什么检查，在什么条件下成立。

不必把每条笔记都写成表格，但影响后续行动的结论，应能回答来源、适用范围与验证方式。这样，当结论失效时，系统才知道该回查哪里，以及哪些后续经验可能受影响。

## 三、VISTA：在推理过程中重新检查视觉证据

[VISTA](https://arxiv.org/html/2610.02200) 把历史回查落实到视觉交互：保存环境返回的所有原始帧，包括动画中间帧，并按回合和帧号索引。画面存储独立于当前上下文，模型可通过 `inspect` 调取多帧、裁剪放大，通过 `read_pixels` 检查像素。它还维护 `GUIDE.md` 和 `WORKING.md`，分别记录可复用理解与当前工作状态。框架不额外训练模型。

这套设计将“保留信息”与“让信息进入上下文”分开。保存一帧画面，并不意味着模型每一步都要读取它；模型可以在形成具体问题后，再决定检查哪个时刻和区域。

例如，要判断某个物体是否在动画途中改变方向，只看动作结束画面可能不够。文字笔记给出先前解释，原始帧则允许模型重新检查解释是否成立。检索因此成为推理的一部分：当前问题指导取证，证据又改变下一步计划。

这里的“无损”指保存环境已返回的原始帧，不代表完整记录了世界。画面之外的隐藏状态、环境未返回的变化，以及模型再次看图时的识别错误，仍然存在。扩大图像也不能创造原始画面中没有的细节。

论文报告的结果与边界包括：

| 实验 | 报告结果 | 解读边界 |
| --- | --- | --- |
| ARC-AGI-3 的 25 个公开游戏 | Opus 5.0 搭配 VISTA 全部完成，RHAE 为 100。 | 属于系统级结果；官方基线与其推理强度不同，不能把差距全部归因于记忆。 |
| BabyVision 的 39 道迷宫与连线题 | 准确率从 41.0% 提升至 63.2%。 | 这些是静态图像题，收益说明局部检查的价值，不能证明历史记忆的收益。 |

上述结果来自[论文报告](https://arxiv.org/html/2610.02200#S4)，未独立复现。作者也指出，公开游戏可能进入模型训练数据，泛化能力仍需在新任务上验证。

对一般系统而言，可迁移的设计思路是：**给模型一个有索引、可检查的证据空间，让它能够随着问题变化重新取证。** 是否保存全部画面、保存多久、提供哪些检查工具，需要按任务成本决定。

## 四、Dreaming：在任务之间修正与组织知识

在线执行时，模型首先要推进任务，未必有时间全面检查旧笔记。可以把一部分整理工作安排在任务间隙：回查记录、验证结论、合并重复经验，调整知识入口。

Anthropic 将这类后台整理称为 [dreaming](https://www.anthropic.com/research/components-of-agent-memory)。它使用上下文和外部存储，不更新模型权重。文中一个宝可梦案例中，模型把地标方位记错，后续行动反复受其误导；整理阶段对照原始会话修正笔记后，后续运行走通了路线。

VISTA 与 dreaming 可以放在两个时间尺度上理解：前者支持执行中的证据检查，后者支持任务之间的知识修订。需要注意，Anthropic 在该文中主要将 memory 定义为跨会话保留的知识；VISTA 的视觉记忆主要服务于持续交互。本文将它们放在一起，是比较外部记录与回查机制，并不意味着两者的任务定义相同。

后台整理可以产生几类结果：纠正错误结论、将个别经历提炼为规则、建立跨材料联系，以及调整未来会话默认加载的内容。整理的依据必须包含原始记录或新验证结果；只围绕旧摘要再次推理，仍可能强化原来的误判。

在知识组织上，Wiki 提供主题导航，原始检索提供细节核查。Anthropic 的内部文档实验中，25 道题的评分标准满足率为：仅搜索 53%，仅 Wiki 最好 48%，组合最好 61%。构建过程达到 128M dreaming token，说明知识整理也有显著成本。这些是[特定实验的结果](https://www.anthropic.com/research/components-of-agent-memory)，不能据此预设所有任务都值得建设 Wiki。

当问题通常只涉及单份文件时，直接检索可能已经足够；当任务反复跨文档建立联系时，预先组织知识才更可能摊薄成本。

## 五、把记录、知识与上下文连接起来

基于上述机制，可以把记忆系统组织为四层。这是一种职责划分，不要求使用四套独立产品。

| 层次 | 保存内容 | 主要职责 |
| --- | --- | --- |
| 原始记录 | 会话、工具返回、画面、动作和验证产物 | 留下回查依据，提供稳定定位方式。 |
| 工作记忆 | 当前目标、进度、待验证假设、下一步计划 | 支持任务接续，及时覆盖失效状态。 |
| 可复用知识 | 经验证的规则、决策理由、Runbook、主题 Wiki | 减少重复探索，说明适用边界。 |
| 会话入口 | 少量关键约束、知识索引、当前任务摘要 | 控制上下文成本，引导进一步检索。 |

一次任务可以这样流转：执行产生记录，模型据此维护工作记忆；重复出现且经过验证的认识进入知识层；高频、稳定的知识进入会话入口。新任务先读入口，再按需要查询知识和原始记录。

信息也应允许反向流动。发现规则与当前观察冲突时，应回到依据，把规则降为待验证假设，补充检查后再修订。若错误已经写入多个摘要，只改原始笔记可能不够，还需要更新关联内容。

例如，排障笔记写道“增加超时可解决请求失败”。要成为可复用知识，至少应补充适用的服务版本、实际失败类型、验证结果与副作用。未来遇到类似症状时，先检查这些条件，再决定是否复用。症状相似只能提供线索。

### 记录必须能够被准确找回

一个证据引用应尽量定位到具体任务、时间、版本和片段。对于视觉记录，还可以关联动作编号与帧号；对于代码判断，可以关联提交及测试产物。

引用的稳定性很重要。若一条经验始终指向不断更新的日志文件或仓库主分支，后来读取时看到的内容可能已经变化，无法验证当初的判断。可以按需使用不可变产物、版本化路径或内容标识。

同时，应明确记录的覆盖范围。测试通过只能支持被测条件下的行为，工具未报告错误也不代表任务整体正确。证据能支撑什么，需要与结论一起说明。

## 六、让模型组织知识，让机制落实可靠性

模型适合根据语义判断哪些经验值得留下、如何分类、什么时候合并或展开。组织方式可以随任务演化，不必预设一套覆盖所有场景的目录。

但模型提出的方案仍需通过运行验证。以下职责即使由模型设计和实现，也需要系统实际落实：

- **持久化与恢复**：写入是否成功，中断后能否接续，错误修改能否回退。
- **权限与作用域**：不同用户、项目和环境的资料能否被正确隔离。
- **并发更新**：多个任务是否覆盖彼此的记录，冲突如何处理。
- **来源与版本**：知识依据是否可定位，旧规则是否仍适用。
- **预算与保留**：存储、检索、上下文和后台整理是否受控。

因此，自主组织与工程约束可以共同存在。可以让模型自由调整知识结构，同时通过版本和检查机制约束错误影响。约束应服务于实际需求，并通过任务结果评价。

保存原始证据也需要取舍。对不可重现、可能影响后续判断的观察，保留价值较高；对容易重新查询的状态，可以减少复制。任务结束后，还可以结合复用频率、敏感程度和存储成本设置保留期限。原始记录与提炼知识不必具有相同生命周期。

## 七、按任务收益评价记忆

记忆系统的收益来自减少重复探索、提高判断正确性和支持任务接续，成本则包括记录、检索、整理和错误复用。文件数量、Wiki 规模和目录整齐程度都不能单独代表效果。

评估时可以关注：

| 维度 | 可观察指标 |
| --- | --- |
| 任务效果 | 完成率、正确率、重复试错次数。 |
| 使用成本 | 检索延迟、上下文消耗、完成时间、维护开销。 |
| 证据质量 | 关键判断能否定位依据，依据是否仍然可读。 |
| 更新能力 | 错误规则多久被发现，修订后是否仍被继续引用。 |

要区分组件收益，可以在同一模型和可比预算下，比较无持久记忆、仅摘要、摘要加原始检索、再增加后台整理等方案。视觉任务还应区分局部检查与历史回查，避免把两种能力的效果混为一谈。对于持续学习场景，也应区分允许继承的历史经验与当前评测答案，防止泄漏影响结果。

落地时可以从很小的系统开始：简短任务入口、必要的执行记录、带依据的经验笔记，以及明确的回查工具。当重复检索、跨任务接续和知识冲突成为实际成本，再引入更复杂的 Wiki、后台整理与依赖管理。

Agent 需要能够高效使用已经形成的认识，也需要在遇到矛盾时重新检查它们。原始记录留下重新判断的机会，检索把证据带回当前问题，知识整理则减少下一次任务的探索成本。三者连通，经历才有机会成为持续改进的知识。
